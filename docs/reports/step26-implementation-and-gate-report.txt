====================================================================================================
2. retrieve.py ARCHITECTURE
====================================================================================================
Layered so that the SEARCH is independent of the MODEL, which is what makes exactness testable:

  NextTokenScorer (Protocol)   [batch of prefixes] -> [batch, vocab] full-vocabulary log-softmax
      |  the only model interface; the search never touches the generator
  SidResolver                  token path -> integer item id, via the CatalogueTrie (fail closed)
  retrieve_certified(...)      exact branch-and-bound          -> CaseRetrieval(status=CERTIFIED)
  retrieve_approximate(...)    bounded level beam              -> CaseRetrieval(status=APPROXIMATE)
  retrieve(...)                dispatches on RetrievalConfig.mode; never upgrades a status
  TigerCaseScorer              binds TigerGenerator to ONE case; encoder runs once, decoder batched
  build_history_input(...)     encoder tokens, byte-for-byte as build_examples builds them
  aggregate_certificate(...)   per-case diagnostics -> the section 15.2 certificate block

  No torch import at module scope: the pure search, resolver and oracle tests run without the ML
  stack.  torch is imported lazily inside the model binding only.

====================================================================================================
3. APPROXIMATE ALGORITHM
====================================================================================================
Level-synchronous bounded beam over the catalogue trie.
  * start from the empty prefix; for each of per_item_tokens levels expand every legal child
    and keep the best `beam` prefixes by (descending score, ascending token path)
  * `prefix_budget` caps total expanded nodes; exhaustion is recorded, never hidden
  * completed paths are ranked and resolved under the frozen score rule
  * every result carries status = APPROXIMATE and retrieval_mode = APPROXIMATE
  * APPROXIMATE output is NON-CANONICAL and the arm refuses it for a canonical comparison
Purpose: iteration, smoke tests, latency and coverage profiling.  Beam 10 000 on the synthetic
oracle catalogue reproduces the exhaustive ranking, which is the test that it is a correct
approximation of the same rule rather than a different one.

====================================================================================================
4. CERTIFIED ALGORITHM
====================================================================================================
Exact branch-and-bound over the catalogue trie keyed by the admissible bound.
  * max-heap over prefixes keyed by S(p); the empty prefix starts at bound 0
  * pop the best prefix, score its legal children with ONE batched decoder call,
    push each child with S(child) = S(p) + log P(child | p)
  * a child that is a complete catalogue path is RECORDED as a candidate
  * T = the k_prime-th best COMPLETED score, once k_prime completions exist
  * a branch is terminated exactly when S(p) < T; the search ends globally when the best
    remaining prefix has S(p) < T
  * prefixes are popped in batches of `batch_prefixes`; batching changes only efficiency, and
    pruning always uses a threshold that is <= the final one, so it stays conservative
  * k_prime is AgentRec-X's `required_frontier` (K_max + |seen|), not a display cut-off
  * `prefix_budget` exhaustion sets budget_exhausted and DOWNGRADES the run to APPROXIMATE
    with comparison_eligible = false (spec 15.2) - a truncated search is never called certified

Measured shape on the frozen cohort (512 cases, real model):
  expansions/case           772.9
  pruned by bound/case      1473.9   (the bound does real work: it removes ~2x what it expands)
  certified items/case      {'max': 118, 'mean': 35.023438, 'min': 22}
  budget_exhausted_cases    0

====================================================================================================
5. COMPLETENESS ARGUMENT
====================================================================================================
Under the frozen rule every score term is a full-vocabulary log-probability, hence <= 0, and a
prefix's terms are unchanged by extension.  Therefore for any extension q of p:

      S(q) = S(p) + SUM_{l>m} log P(.)   <=   S(p)

so S(p) bounds every item in the subtree rooted at p.  The search only ever discards a branch
when its bound is below T, and T only increases; every popped bound is >= every completion
beneath it.  Hence no unvisited item can enter the certified frontier and the returned top-
k_prime is the true top-k_prime over the ENTIRE valid catalogue.

The precondition is enforced, not assumed: assert_next_log_probs_admissible rejects any batch
that is non-finite or has a positive entry (i.e. is not a full-vocabulary log-softmax), and
scoring.assert_monotone_prefix_bound is checked against real model output in G15.

Exhaustive-vs-truncating is proved mechanically in two independent ways:
  * on oracle catalogues, k_prime >= catalogue size makes the search enumerate everything:
    prefixes_expanded == nodes - leaves, nodes_pruned_by_bound == 0, and every catalogue item
    is returned (asserted in the test suite)
  * against a brute-force oracle, CERTIFIED top-K == oracle top-K for K in {1,2,3,5,10,20}

6. RESOLVER AND COLLISION SEMANTICS
====================================================================================================
  R1 a path that is not a COMPLETE catalogue path yields NO candidate
  R2 a complete catalogue path yields exactly the item id(s) at that trie leaf
  R3 SID collision (several items on one leaf): the SMALLEST item id wins, and the collision is
     counted and reported.  The frozen Step-2.4F assignment has post-dedup collisions 0, so a
     nonzero count FAILS G14 rather than being tolerated: observed 0
  R4 the PAD sentinel is never tokenisable, never resolvable, never a candidate
  R5 duplicate resolved item ids are de-duplicated keeping the highest score and earliest rank
  R6 item ids outside 1..156746 are refused (asserted in the arm before scoring)
  R7 non-finite scores are refused (asserted in the search and again by the evaluator)

BOUNDARY DISCLOSURE - where canonical identity lives, and why it is not in retrieve.py
  The task's retention list asks for `parent_asin` per returned item.  AGENTS.md section 19.2
  rule 1 forbids canonical identity anywhere under `backends/` or `recommendation/backends/`,
  and contracts.py states the same absence structurally ("no parent_asin appears in any type,
  field or artifact - canonical identity is re-attached outside this boundary").  The two are
  reconciled by keeping the identity fields exclusively in the AgentRec-X layer:
    * retrieve.py / retrieve_cli.py return INTEGER item ids plus resolver provenance only;
      the artifact contains no parent_asin and no target;
    * experiments/tiger_retrieval_arm.resolve_candidate_identities re-attaches parent_asin
      from the frozen mappings and retains, per candidate: parent_asin, semantic_id, score,
      rank, retrieval_mode, checkpoint sha256, SID artifact sha256 and resolver provenance.
  If the intent was instead to carry parent_asin inside the backend, that is a change to the
  boundary rule and needs an explicit decision; it was not assumed here.
