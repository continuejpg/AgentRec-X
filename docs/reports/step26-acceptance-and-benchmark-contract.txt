1. THE FROZEN ITEM SCORE (restated, unchanged)
--------------------------------------------------------------------------------
For catalogue item i with token path t(i) = (t_1..t_M), M = per_item_tokens = 4:

  score(i | history) = SUM over l=1..M of log P_model(t_l | history, t_<l)

P_model is the softmax over the FULL generator vocabulary (vocab_size 1028), raw logits,
unmodified. EOS is NOT a term; it only lets the search recognise a completed path. No
renormalisation over valid children. No length normalisation. No temperature.

ADMISSIBILITY (section 5.3): every term is a log-probability, hence <= 0, and for a fixed
prefix every extension keeps the first m terms unchanged. Therefore for any q >= p:

  S(q) = S(p) + SUM_{l>m} log P(.)  <=  S(p)

so S(p) is an admissible upper bound on every item in the subtree rooted at p. This is the
entire basis of CERTIFIED mode.

--------------------------------------------------------------------------------
2. RETRIEVAL MODES
--------------------------------------------------------------------------------
APPROXIMATE
  purpose       engineering iteration, smoke tests, latency profiling, coverage exploration
  algorithm     level-synchronous bounded beam over the catalogue trie; at most `beam`
                prefixes survive each level; `prefix_budget` caps total node expansions
  status        "APPROXIMATE"
  metrics from this mode are NON-CANONICAL and must never appear in the canonical table

CERTIFIED
  purpose       canonical evaluation ONLY
  algorithm     exact branch-and-bound over the catalogue trie keyed by the admissible bound
                S(p), max-heap, running threshold T = the required_frontier-th best COMPLETED
                item score; a branch is terminated exactly when S(p) < T; global termination
                when the best remaining prefix has S(p) < T
  status        "CERTIFIED"
  equivalence   for every case the returned top-required_frontier is the true top-
                required_frontier over the ENTIRE valid catalogue under the score rule of
                section 1, because no unvisited item can enter the frontier (section 5.3)

BUDGET AND DOWNGRADE (section 15.2)
  if any case exhausts `prefix_budget` before global termination, that case is recorded in
  `budget_exhausted_cases`, the run's `retrieval_status` is REWRITTEN to APPROXIMATE, and
  `comparison_eligible` becomes false. A budget-exhausted run is NEVER reported as CERTIFIED.

--------------------------------------------------------------------------------
3. RESOLVER AND COLLISION SEMANTICS
--------------------------------------------------------------------------------
flow (TIGER side, integer item-id space only):
  token path -> CatalogueTrie.item_for_path -> backend/AgentRec-X integer item id

Parent_asin NEVER appears inside backends/ or recommendation/backends/ (AGENTS.md 19.2 rule 1;
contracts.py states the same absence structurally). Canonical identity is re-attached in the
AgentRec-X layer outside the adapter, in the Step-2.6 arm, and that is where the
parent_asin / resolver-provenance fields required by the task are retained.

rules, all deterministic and all fail-closed:
  R1  a token path that is not a COMPLETE catalogue path yields NO candidate
  R2  a token path that is a complete catalogue path yields exactly the item id(s) registered
      at that trie leaf
  R3  SID collision (more than one item at one leaf): the SMALLEST item id is returned and the
      collision is recorded. The frozen assignment (Step 2.4F) has post-dedup collisions 0,
      so any nonzero collision count FAILS G14 rather than being tolerated
  R4  a PAD sentinel is never tokenisable, never resolvable, never a candidate
  R5  duplicate item ids in one case are de-duplicated keeping the highest score and the
      earliest rank
  R6  item ids outside [1, 156746] are refused
  R7  scores that are NaN or +-Inf are refused; a non-finite score count > 0 FAILS the contract

failed or APPROXIMATE run, with the offending counts, and no comparison against SASRec,
Two-Tower or GenRec-v0 is made.

CERTIFIED means, mechanically:
  status == "CERTIFIED"
  method == "branch_and_bound"
  certificate_holds_for_all_cases == true
  budget_exhausted_cases == 0
  the admissibility predicate of section 1 held for every scoring call used
