  BEFORE H8 ran, i.e. before any TIGER recommendation metric existed.  They are reported here
  rather than quietly folded in:

  (a) experiments/tiger_retrieval_arm.py -- PROTOCOL PARITY BUG FIX.
      The accepted arm forwarded `case.train_history` as the history handed to the evaluator.
      `evaluate_batched` masks exactly the history it is given, so the validation target would
      have remained unmasked and eligible, silently changing every metric.  Every accepted arm
      in benchmark_public.py forwards `case.test_history` (= train_history + validation_target),
      which is also what `required_frontier = K_max + |seen|` assumes.  The arm now does the
      same for the test cohort, and raises for an unknown cohort instead of guessing.
      Found by reading the accepted arms while H7 was still running; H7 itself is unaffected
      because the producer consumes the handoff directly and never uses this arm.
  (b) experiments/step26_gates.py -- determinism checks now REPORT their scope.
      G14.7/G15.3 previously required a second full-cohort artifact and failed when none was
      supplied.  The frozen criterion is "two independent runs over the same input", and a
      prefix subset is the same input for the cases it contains, so the check now compares an
      independent re-run against the corresponding prefix of the canonical artifact and prints
      how many cases were compared.  No threshold was loosened; the claim's scope is now
      explicit.
