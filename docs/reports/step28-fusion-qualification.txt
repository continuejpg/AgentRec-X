19. EXACT EVIDENCE-SUPPORTED FUSION CONCLUSION
====================================================================================================
  Three quantities, kept separate:
    oracle complementarity   138 TIGER-only users outside SASRec u Two-Tower at K=10 (frozen)
    actual fusion capture    69 of those 138 become fused hit@10 (50.0%)
    net metric change        Recall@10 +0.00065 (+3.72%), net +13 hits, from +115 gained and -102

  Descriptive outcome, using the contract's own vocabulary, both supported by counts:
    * 'TIGER provides unique oracle coverage but RRF captures only part of it' -- 69/138 =
      50.0%% at K=10, rising to 62.3%% at K=20; 236 oracle hits still outside the fused top-10.
    * 'RRF gains TIGER-specific hits but displaces comparable existing hits' -- 115 gained vs
      102 lost at K=10, netting only +13.

  What is NOT claimed: that TIGER is useless for fusion (it is the sole reason D > A, and the
  three-source configuration beats the two-source control on every reported quantity), and
  that TIGER fusion is a solved win (the net gain is small and the displacement is large).
  The honest summary is that rank-only RRF converts part of TIGER's complementarity into a
  small but consistent improvement, at the cost of displacing a comparable number of hits the
  existing pair already had.

20. IS A LATER WEIGHTED / CALIBRATED FUSION EXPERIMENT JUSTIFIED?
====================================================================================================
  The evidence points AT it but does not authorise it.  Supportive: the two-source diagnostics
  B and C both fall below A, while the three-source D exceeds A on all nine quantities, so the

  Recommendation: a weighted/calibrated fusion milestone is scientifically justified ONLY as a
  new pre-registered milestone with its own frozen criterion and a declared uncertainty method.
  It was NOT run here, and per the contract it is not run automatically.
