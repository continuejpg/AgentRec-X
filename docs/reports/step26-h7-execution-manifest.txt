--- why batch_prefixes is frozen ---
Cross-batch-size scoring differs in the last few ULPs (different GEMM reduction shapes) while
the certified ORDER is unchanged.  H7 therefore fixes batch_prefixes = 256 and records it, so
the artifact is reproducible bit-for-bit for that fixed configuration.

--- why this prefix budget ---
Measured per-case expansions on the accepted implementation (512 real cohort cases):
  min 769   p50 769   p95 771   p99 962   max 1152   mean 772.9
  pruning: min 0   max 5447   mean 1473.9
  largest observed frontier 118; the full cohort's largest is 701, i.e. ~6x -> projected worst
  case ~= 7000 expansions.  Budget 1000000 is ~870x the largest observed and ~140x the projected
  worst case, so it cannot bind in practice.  It is a safeguard against a pathological case
  running unbounded, NOT an approximation knob: if it ever binds, the run is downgraded and
  H7 certification FAILS rather than being repaired in place.

--- why H7 is NOT sharded ---
Case-range sharding is available (the search is case-independent) but would require a case-range
driver.  The accepted retrieve_cli.py exposes only --limit (a prefix), and modifying it would
change the very hash this manifest freezes.  H7 therefore runs as ONE process over all 20 000
cases, so the seven accepted Step-2.6 files stay byte-identical and no case index is remapped.
Interruption semantics: a crash or stop means the artifact is incomplete and H7 is re-run from
scratch; no partial artifact is ever treated as certified.

--- fail-closed runtime invariants enforced by the implementation ---
  all model scores finite                        (assert_next_log_probs_admissible, per call)
  log-probability admissibility assertions pass  (every scored batch, plus G15.5 on real output)
  all returned SIDs valid                        (every path is a complete 4-level trie path)
  no unresolved identity / no invalid candidate  (arm refusal + G14)
  no duplicate final identity                    (dedup by item_id, highest score kept)
  no protocol mismatch                           (G16)
  any violation is fail-closed: the process raises rather than skipping a case
