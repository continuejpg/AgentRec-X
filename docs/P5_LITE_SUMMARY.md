## 一页总结

**主要收益**：Phase 4 把“多轮购物”从单轮检索变成了可核验的状态机。60 个有明确意图期望的
轮次中，基线 0 个正确，Phase 4 全部正确；基线忽略价格类约束，在 380 个展示商品中违反 43 次
（11.3%），Phase 4 在 319 个展示商品中 0 次；基线展示 118 个目录无法判定的商品，Phase 4 为 0；
8 个冲突/不可验证场景基线全部无法闭环，Phase 4 全部完成“提问 → 回答 → 重推”。逐商品理由
561 条声明全部可对目录核验，而基线没有理由字段。

**失败案例**：基线的 43 次违反集中在 7 个价格场景（12 次）、4 个冲突场景（30 次）和 1 个
不可验证场景（1 次）；60 个有期望的意图轮全部错误；8 个澄清场景全部失败。Phase 4 在这 36 个场景中
没有失败；剩余问题不是场景失败，而是覆盖边界：自然语言 hard brand / 类别替换解析不支持、
每个 session 只问一次、进程内 pending、浏览器未验证 410 过期。

**技术取舍**：意图是现有 `PreferenceMemorySnapshot` 的只读投影 + 本轮 extraction 预览，不新建
存储；硬/软由措辞保守判定，模糊表达默认 soft；价格不进 lexical query，仍由确定性 eligibility
检查；澄清是 suspension，不伪造完成；理由完全由目录记录生成，没有 LLM 评分器。未改 RRF、
Learned Ranker、候选深度或最终排序，p50 延迟与基线基本一致。

**证据局限**：36 个构造场景、12 段历史、每场景一次运行，无置信区间/显著性检验；基线是
“功能缺失”对照而非调优系统，硬约束比率的分母不同；多轮“最终列表/解释一致率”没有逐轮落盘，
只能引用 Phase 3.1 的单轮 38/38 与 4.2 的端到端契约测试；所有结论是工程验证，不能外推为
线上用户效果。

## 未验证的关键局限

1. “多轮最终列表/解释一致率”没有 76 轮逐轮统计；只有 Phase 3.1 单轮 38/38 和 4.2 的一次
   端到端断言。
2. 浏览器未验证 410 过期（TTL 30 分钟）；仅 API 测试覆盖。
3. 无真实用户、无跨重启/多 worker、无线上延迟分布。
4. 单次运行，无方差估计；场景标签由人工规则生成，不是独立标注员。
