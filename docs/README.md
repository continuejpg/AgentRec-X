## Documentation conventions

Two rules replaced the earlier three-way split, because the old split let a stale document
keep calling itself "current":

1. **Authority order** — worktree code > the "Current" group above > "History". A document in
   the History group never describes the present, and says so at its top.
2. **Evidence layers are reported separately** — engineering correctness, recommendation
   quality, system completeness and delivery/persistence are four different claims. A PASS in
   one never implies another; quality that is not established is written `NOT ESTABLISHED`.

Numbers quoted in these documents come from a committed artifact or an executed smoke run, and
each is attributed. Where a value is not recorded, the text says so rather than estimating it.
No relevance, satisfaction or conversion claim is attached to preference-aware reranking,
because no preference-conditioned relevance labels exist.
